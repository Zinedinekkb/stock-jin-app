# สิทธิ์การเข้าถึงตามตำแหน่งงาน (Access Control)

> **สำคัญ: ระบบนี้บังคับใช้ฝั่ง client (หน้าเว็บ) เท่านั้น**
> Firestore rules ในโปรเจกต์ยังอนุญาตให้ผู้ใช้ที่ได้รับอนุมัติทุกคนอ่าน `documents` และ `leaves` ได้
> ผู้ใช้ที่มีความรู้ทางเทคนิคจึงยังเรียกอ่านข้อมูลของคนอื่นผ่าน SDK/DevTools ได้
> การบังคับใช้ฝั่งเซิร์ฟเวอร์ (rules ตามตำแหน่ง) **ยังไม่รวมอยู่** — ไม่ได้แก้ `firestore.rules`
> และ rules tests รันในสภาพแวดล้อมที่พัฒนานี้ไม่ได้ (ไม่มี JDK) ถ้าข้อมูลต้องแยกขาดจริง ต้องเพิ่ม rules แยกต่างหาก

## กลุ่มสิทธิ์

ระบบจัดผู้ใช้เข้ากลุ่มจาก `role` และ `position` (ฟังก์ชัน `getUserAccessGroup` ใน `app/config/accessMatrix.js`):

| กลุ่ม | ตัวอย่างตำแหน่ง |
|---|---|
| แอดมิน | `role = admin`, หรือตำแหน่งมีคำว่า ผู้ดูแลระบบ / ผู้จัดการ / เจ้าของ / admin / owner |
| คลัง/สต็อก | เจ้าหน้าที่สต็อก, คลัง, พัสดุ |
| ครัว | เชฟ, แม่ครัว, ครัว |
| การเงิน | แคชเชียร์, การเงิน, บัญชี |
| หน้าร้าน | พนักงานเสิร์ฟ, หน้าร้าน, บริการ, บาริสต้า |
| จัดส่ง | พนักงานจัดส่ง, ขนส่ง, ไรเดอร์ |
| พนักงานทั่วไป | ตำแหน่งอื่นทั้งหมดที่ไม่ตรงกลุ่มด้านบน (รวมถึงตำแหน่งว่าง) |

คีย์เวิร์ดตำแหน่งใช้ชุดเดียวกับ `POSITION_CLUSTERS` (แท็บงานตามแผนก) ตำแหน่ง "หัวหน้า"/"บริหาร" ที่ไม่ใช่แอดมินจะเป็น "พนักงานทั่วไป"

## ตารางสิทธิ์

| ฟีเจอร์ | แอดมิน | คลัง | ครัว | การเงิน | หน้าร้าน | จัดส่ง | ทั่วไป |
|---|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| แดชบอร์ด | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| ดูคลังสินค้า | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| สร้างรายการเบิก/รับ | ✓ | ✓ | ✓ | ✓ | – | ✓ | – |
| สถานะ/ประวัติรายการ | ✓ | ✓ | – | ✓ | – | ✓ | – |
| ยืนยันยอดสต็อกจริง | ✓ | ✓ | – | – | – | – | – |
| เอกสาร | ทั้งหมด | ของตน + เบิก/รับ | ของตน | ของตน + เบิก/รับ | ของตน | ของตน | ของตน |
| เข้า-ออกงาน / ใบลา | ทั้งหมด | ของตน | ของตน | ของตน | ของตน | ของตน | ของตน |
| การแจ้งเตือน | ทุกหมวด | ไม่เห็นหมวดผู้ใช้/ลา | เช่นเดียวกัน | เช่นเดียวกัน | เช่นเดียวกัน | เช่นเดียวกัน | เช่นเดียวกัน |

แจ้งเตือนหมวด "เบิก/รับ" แสดงเฉพาะกลุ่มที่เปิดดูสถานะรายการได้

เฉพาะแอดมิน (เหมือนเดิม): จัดการบัญชีผู้ใช้, ตั้งค่าร้าน, แก้ไข/เพิ่ม/ลบสินค้า, จัดการหมวดหมู่, อนุมัติ/ยกเลิก/แก้ไขรายการเบิก-รับ, ลบประวัติ, ส่งรายงาน LINE, อนุมัติลา/ผู้ใช้

## ข้อมูล "ของตน" หมายถึงอะไร

- **เอกสาร**: เห็นเมื่อสร้างโดยตนเอง (`createdByUid` ตรงกับ uid) หรือถูกมอบหมาย (`assignedTo` / `assignedToUid`) เอกสารเก่าที่ยังไม่มี `createdByUid` จะเทียบจากชื่อผู้สร้าง (`createdBy`) เพื่อไม่ให้เอกสารหายจากเจ้าของ
  กลุ่มการเงินและคลังเห็นเอกสารประเภทรายการเบิก/รับ (มี `transactionId` หรือหมวดใบรับเข้า/ใบเบิก) ของทุกคนด้วย
  รายงานอัตโนมัติ (ผู้สร้าง "ระบบอัตโนมัติ") เห็นเฉพาะแอดมิน
- **ใบลา**: เห็นเมื่อ `userId` / `createdByUid` ตรงกับ uid ใบลาเก่าเทียบด้วยชื่อ `userName`
- เอกสารและใบลาที่สร้างใหม่ทุกชิ้นจะบันทึก `createdByUid`

## จุดที่โค้ดเกี่ยวข้อง

- `app/config/accessMatrix.js` — ตารางและฟังก์ชัน `canAccess`, `getUserAccessGroup`, `canSeeDocument`, `canSeeLeave` (pure, ทดสอบด้วย `npm run test:unit`)
- `app/utils/permissions.js` — `hasPermission` / `canVerifyStock` อ่านจากตารางนี้
- `app/config/navigation.js` — ซ่อนเมนูที่ไม่มีสิทธิ์
- `app/page.js` — guard แท็บ (ถ้าสิทธิ์หายระหว่างเปิดแท็บจะเด้งกลับแดชบอร์ด) และกรองการแจ้งเตือน

## สิ่งที่ยังไม่ได้บังคับใช้

- Firestore/Storage rules ยังไม่จำกัดการอ่าน `documents`, `leaves`, `transactions` ตามตำแหน่ง (ฝั่ง client เท่านั้น)
- ไฟล์ PDF ใน Storage ที่รู้ URL ยังเปิดได้
- ตำแหน่งที่เป็นแอดมินจากคำในชื่อตำแหน่งแต่ `role = staff` จะได้สิทธิ์แท็บของแอดมินในตารางนี้ แต่การกระทำที่เช็ค `role === 'admin'` (เช่น อนุมัติลา) ยังต้องใช้ role จริง

ในโหมดเดโม (`NEXT_PUBLIC_DEMO_MODE=true`) สลับบทบาททั้ง 7 กลุ่มได้จากปุ่มลอยด้านล่าง และกดไอคอน ⓘ เพื่อดูตารางสิทธิ์
